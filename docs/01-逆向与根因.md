# 01 · 逆向分析与 iOS 17 失效根因

对象：`LSTimeSeconds(roothide)-0.0.5-1-iphoneos-arm64e.deb`（作者 b4db1r3 & SINI）

> 注：同批次的 `LSTimeSeconds (iOS 15 - 16)-0.3-iphoneos-arm64` 文件实际是一个
> YouRepo 的 **404 HTML 页面**（`<!DOCTYPE html>` 开头，65 KB），不是合法 deb，无从分析。
> 因此全部结论来自 roothide 版。

---

## 一、包结构与二进制概况

```
Library/MobileSubstrate/DynamicLibraries/LSTimeSeconds.dylib   # FAT: arm64 + arm64e
Library/MobileSubstrate/DynamicLibraries/LSTimeSeconds.plist   # Filter: com.apple.springboard
Library/PreferenceBundles/LSTSPrefs.bundle/                    # 设置面板
Library/PreferenceLoader/Preferences/LSTSPrefs.plist
```

dylib 链接 `@loader_path/.jbroot/usr/lib/libsubstrate.dylib`，配置域 `com.b4db1r3.lstsprefs`。

主要符号（来自 symtab 与 `__objc_methname`）：

```
__Z7isIOS15v  __Z7isIOS16v  __Z9loadPrefsv
_secondsTimer2  _isEnable  _isUsingADO  _timeFormat  _timeFormatCase
```

## 二、根因 1：构造函数里的版本硬编码

`%ctor` 等价逻辑（由 arm64 切片 `0x4318` 起反汇编还原）：

```objc
loadPrefs();
if (isIOS15()) {
    // Hook SBFLockScreenDateView: layoutSubviews
    // class_addMethod: handleTap: / expectedLabelWidth: / updateTimeLabel
} else if (isIOS16()) {
    // Hook CSProminentDisplayViewController: viewWillAppear: / dealloc
    //      SBBacklightController: dealloc / backlight:didCompleteUpdateToState:forEvent:
    //      SBDashBoardBiometricUnlockController: setAuthenticated:
    //      CSProminentTimeView: layoutSubviews
    // class_addMethod: setupOrUpdateTimer / updateTimeLabel / isShowingSeconds / ...
} 
// ← 没有 else，iOS 17 直接穿过去，一个 Hook 都没有
```

`isIOS15()` / `isIOS16()` 的实现是拿 `[[UIDevice currentDevice] systemVersion]`
做 `hasPrefix:`（常量 `"15"` / `"16"`，位于 `__cstring` 偏移 27149/27152）。
iOS 17.2.1 的版本字符串是 `"17.2.1"`，两条都不成立。

**结论：原版在 iOS 17 上是彻底的空操作，这就是"装了没反应"的第一根因。**

## 三、根因 2：设置通知名拼错

- `Root.plist`（二进制 plist）里 `timeFormatCase` 的 `PostNotification` =
  `com.b4db1r3.ocd/reloadPrefs`（注意 `ocd`）。
- dylib 内部常量是 `com.b4db1r3.lstsprefs/reloadPrefs`。

两者对不上，改设置永远通知不到 SpringBoard。即使 Hook 挂上了，也必须注销才能生效。

## 四、根因 3：旧键名把秒数默认关掉

原版开关键是 `isUsingADO`（"Using Always On Display"，默认 `false`）。
本机磁盘上残留了这份配置，而新实现读的是新键 `showSeconds`。
如果代码写成"新键读不到就回退旧键"，就会拿到 `false` → 定时器直接 `invalidate`，
所有格式化与缩放分支都不执行。

实测日志（`/var/mobile/Library/LSTimeSeconds.log`）中出现了
`loadPrefs: enabled=1, showSeconds=0, mode=1, scale=0.77` 而
`CSProminentTimeView didMoveToWindow: ON SCREEN` 正常，
即**视图抓到了、广播也收到了，但秒数被配置判成关闭**。

修复：彻底切断与 `isUsingADO` 的回退绑定，`showSeconds` 缺省即 `true`。

## 五、根因 4：文字宽度与字号被系统回灌

### 宽度

`CSProminentTimeView` 的 `expectedLabelWidth:`（原版在 iOS 16 分支里补过）按
`HH:mm` 的 5 字符宽度排版。追加秒数后为 8 字符，若不自算宽度，文字会被挤压或截断。

### 字号

真正导致"每秒抽搐一下"的是这段逻辑：

```objc
CGFloat newPt = label.font.pointSize * scale;   // ← 从当前值取基准
```

每秒 `layoutSubviews` 执行一次：第一次 80 → 70.4；系统内部把 label 还原成 80；
下一秒又从 80 算出 70.4 …… 字号在两值之间来回震荡，肉眼看就是时钟大小不停变化。

正确做法是把**首次读到的原始字号**缓存在实例上（`objc_setAssociatedObject`），
之后每次都用 `originalPointSize * scale`，并对"当前字号已接近目标"做 0.5 pt 的防抖。

## 六、iOS 17 的锁屏时钟在哪

- 时钟渲染在 `CoverSheetKit.framework`：
  `CSProminentDisplayViewController` 持有 `CSProminentDisplayView`，
  其 `_timeView` 是 `CSProminentTimeView`（继承链
  `CSProminentTextElementView` → `CSProminentElementView` → `UIView`）。
- `CSProminentTimeView` 持 `_baseFont` / `_timeFormatter` / `_numberingSystem`；
  文本实体在 `CSProminentTextElementView._textLabel`（运行时常见类
  `_UIAnimatingLabel`）。
- 时间推进靠内部 `_date`。`_updateTimeString` 类方法格式化的是这个 `_date`，
  **不是 `[NSDate date]`**。系统的 `_date` 只在点亮屏幕或整分钟推进，
  所以只"刷字符串"不改 `_date`，秒数永远停在同一秒 —— 这是"只在重新进屏保时更新"的机理。

## 七、修复映射表

| 原版问题 | 本仓库做法 |
|---|---|
| 版本硬编码 | 删掉版本判断，直接挂 `CoverSheetKit` 相关类 |
| 生命周期不可靠 | 以 `didMoveToWindow` / `viewWillAppear` / `viewIsAppearing` / 背光状态驱动注册 |
| `_date` 不推进 | 每秒 `object_setIvar(view, "_date", now)` |
| 只走一条渲染通道 | `setOverrideString:` + `textLabel` + `_updateTimeString` + `setDate:` 四通道 |
| 宽度按 5 字符 | 按当前格式实测 `sizeWithAttributes:` 重算宽度并居中 |
| 字号循环缩放 | 首次锚定 `originalPointSize`，之后只乘固定比例，带 0.5 pt 防抖 |
| 长按壁纸编辑卡死 | `isEditingPoster()` 检测 `usesEditingLayout` / `Switcher` / `Gallery` 后静默旁路 |
| 通知名拼错 | 面板与本仓库统一用 `com.b4db1r3.lstsprefs/reloadPrefs` |
| 旧键混淆 | 只用 `isEnable` / `fontScale` / `yOffset`，读取走 `CFPreferencesCopyAppValue` + 文件兜底 |
