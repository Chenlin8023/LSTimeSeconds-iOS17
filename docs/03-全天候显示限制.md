# 03 · 全天候显示（AOD）限制说明

## 结论

**本插件不支持在 AOD 暗屏状态下持续走秒，这是系统层面的限制，不是实现缺陷。**

亮屏锁屏：秒数每秒递增。
熄屏 / 进入 AOD：刷新暂停（省电），点亮瞬间立即接上真实秒数。

---

## 一、为什么暗屏下秒数走不动

### 1. 硬件：LTPO 把刷新率锁到 1 Hz

iPhone 14 Pro / 15 Pro 进入 AOD 后，ProMotion LTPO 面板的最低刷新率会降到 **1 Hz**，
由显示驱动在硬件层面接管，不是 App 能改的。即使 App 每秒提交 1 帧，面板也只按 1 Hz 出图。

### 2. 系统：BacklightServices 的 Flipbook 机制

iOS 16 起引入 `BacklightServicesHost`：

- `BLSHAlwaysOnPresentationEngine` 在熄屏前把画面**预录**成一组定格帧（Flipbook session）；
- 暗屏期间由引擎回放/短路这些帧，**常规的 UIView 树更新不会被重新合成到屏幕**；
- 系统还会对暗屏期间的渲染做节流（power budget / render budget），
  非必要的 `setNeedsDisplay` 直接被丢弃。

结果：`NSTimer` 或 `dispatch_source` 每秒都在跑、字符串也确实改了，
**但改动到不了屏幕**。这与原版插件无关 —— 任何"每秒改 UILabel"的实现都会遇到同一堵墙。

### 3. 系统自己怎么做的

苹果的做法是**只让秒跳变有意义的部分按整分钟更新**：AOD 下系统时钟显示
`HH:mm`，只在分钟边界触发一次全局重绘；秒数根本不在 AOD 的渲染清单里。

---

## 二、我们验证过的尝试（未采用）

做了一个实验分支（`com.sini921.lstimeseconds.aod`）：

| 尝试 | 结果 |
|---|---|
| `NSTimer` → `GCD dispatch_source`（`DISPATCH_SOURCE_TYPE_TIMER`，20 ms leeway） | 定时器稳定触发，但 UI 更新仍被暗屏合成层丢弃 |
| 每次更新包一层 `CATransaction` + `setDisableActions:YES` + `commit` / `flush` | 亮屏有效；暗屏仍不落地 |
| 直接对 `label.layer` 调 `setNeedsDisplay` | 同上 |
| 保留定时器不暂停（不在 `hasBlankedScreen` 时 `stopTimer`） | 稳定复现"暗屏不动、亮屏瞬间跳到正确时间" |

根本原因在前两条（硬件 1 Hz + Flipbook 短路），**应用层无法绕过**。
强行保留高频刷新还会带来额外唤醒与耗电，因此正式版选择：暗屏暂停、亮屏立即恢复。

---

## 三、行为定义（正式版）

| 状态 | 定时器 | 屏幕表现 |
|---|---|---|
| 亮屏解锁态 / 锁屏亮屏 | 运行（1 s） | 秒数每秒递增 |
| 熄屏（blank） | 暂停 | 不刷新，省电 |
| AOD 暗屏 | 暂停 | 显示最后一次的 `HH:mm:ss`，点亮后 1 帧内跳到正确值 |
| 回到亮屏（背光 `state != 2`） | 立即恢复 | 立刻校准 |

对应代码：`SBBacklightController -backlight:didCompleteUpdateToState:forEvent:` 里
`state == 2` 视为 blank，其余视为唤醒；`hasBlankedScreen` / `lockstate` /
`hid.displayStatus` 三个 Darwin 通知做交叉兜底。

> 历史坑：早期版本把唤醒条件写成 `else if (state == 1)`。而真机点亮时上报的是
> `state = 0`，于是定时器一旦在熄屏时停掉就**再也不会恢复**，表现为"时间彻底冻结，
> 只有重新进屏保才更新"。现在条件改成 `state != 2`。

---

## 四、如果你确实需要暗屏秒数

可选方向与代价：

1. **常亮屏 + 关闭自动锁屏**（设置 → 显示与亮度 → 自动锁定 → 永不）：
   秒数会一直走，但屏幕全亮，耗电与烧屏风险显著。
2. **改用 AlwaysOn 类工具**：把锁屏常驻显示从系统的 Flipbook 模式切到常规渲染模式，
   由那些工具承担耗电与兼容性风险。
3. **接受整分钟精度**：在 AOD 下只显示 `HH:mm`，亮屏后再显示秒 —— 这也是系统的默认哲学。

本插件不内置以上任何一种，避免把耗电与不稳定带给用户。

## 五、2026-11-06 补充：待机显示（StandBy）与措辞修正

- 新增调研文档 [`06-待机显示与全天候显示可行性.md`](06-待机显示与全天候显示可行性.md)：
  iOS 17 的 StandBy 内部代号是 **Ambient**（`AmbientUI.framework` / `SBAmbientPresentationController`），
  其 Digital 表盘默认按分钟更新，**亮屏 StandBy 下可以做到秒级**；变暗/夜间（1Hz）仍受本文所述的
  Flipbook 限制，和 AOD 是同一堵墙。
- 本文第一节“硬件把刷新率锁到 1Hz”的表述不够准确：1Hz 是 iOS 的功耗策略，
  由 `BacklightServicesHost` 的 Flipbook/1Hz 机制强制执行，不是不可绕过的硬件锁；
  但应用层（定时器改 UILabel）依然绕不过，结论不变。详见文档 06 第 3 节。
