# 04 · 发布越狱源（让其他用户可以加源安装）

本仓库的包同时出现在两个源里：

| 源 | 地址 | 说明 |
|---|---|---|
| **统一源（主推）** | `https://chenlin8023.github.io/` | 账号根站，仓库 `Chenlin8023.github.io`，收录全部插件 |
| 单项目源 | `https://chenlin8023.github.io/LSTimeSeconds-iOS17/` | 本仓库 `gh-pages` 分支，只含 LSTimeSeconds |

两者都是 GitHub Pages 静态 APT 源，Sileo / Zebra / Cydia 都能直接添加。
给用户推荐**统一源**，装别的插件不用再加一次。

## 一、给用户看的地址

```
https://chenlin8023.github.io/
```

| 客户端 | 添加方式 |
|---|---|
| **Sileo** | 软件源 → `+` → 粘贴地址 → 添加（或点落地页的「在 Sileo 中添加」） |
| **Zebra** | Sources → `+` → 粘贴地址 |
| **Cydia** | 软件源 → 编辑 → 添加 → 粘贴地址 |

落地页：<https://chenlin8023.github.io/>（含一键跳转按钮与各插件说明）

## 二、原理

GitHub Pages 只能提供静态文件，而 APT 源的本质就是"静态文件 + 两个索引"：

```
（gh-pages 分支根目录）
├── index.html      # 落地页
├── .nojekyll       # 让 Pages 跳过 Jekyll 处理，按原始文件发布
├── debs/           # 所有 .deb
│   ├── com.sini921.lstimeseconds_0.0.7-1_iphoneos-arm64e.deb
│   └── com.sini921.lstimeseconds_0.0.8-1_iphoneos-arm64e.deb
├── Packages        # 每个 deb 一条 stanza（含 Filename / Size / SHA256）
├── Packages.gz     # 上面文件的 gzip（Sileo 优先取压缩版）
├── Packages.xz     # xz 版
└── Release         # 源元信息 + Packages 各变体的 MD5/SHA256
```

- `Release` 里的 `Architectures` 必须包含包的架构，否则客户端会把包过滤掉。本仓库写的是
  `iphoneos-arm64e iphoneos-arm64 iphoneos-arm`，所以 RootHide（arm64e）与 rootless（arm64）
  两种客户端都能看到。
- `Packages` 里的 `Filename` 是**相对仓库根**的路径（`debs/xxx.deb`），客户端会拼上源地址下载。

## 三、发布新版本（三步）

### 1. 把新 deb 放进仓库目录

```bash
mkdir -p repo/debs
cp com.sini921.lstimeseconds_0.0.9-1_iphoneos-arm64e.deb repo/debs/
```

> 旧版本**不要删**。同名包的多版本共存是 APT 的正常形态，客户端默认装最高版本，
> 用户仍可用 `apt install com.sini921.lstimeseconds=0.0.7-1` 精确回退。

### 2. 重新生成索引

```bash
python3 tools/make_repo.py --dir repo
```

脚本只用 Python 标准库：自己解析 `ar` + `tar` 取 control，不要求装 `dpkg-dev`；
会输出 `Packages` / `Packages.gz` / `Packages.xz` / `Release`（含 MD5 与 SHA256）。

可选参数：

```bash
python3 tools/make_repo.py --dir repo \
  --origin "Chenlin8023 Repo" \
  --label  "Chenlin8023" \
  --description "iOS 17 tweak 修复与增强 (RootHide / roothide)"
```

### 3. 更新 gh-pages 分支

```bash
# repo/ 目录内容就是 gh-pages 的根
git -C repo add -A
git -C repo commit -m "repo: 发布 v0.0.9"
git -C repo push origin gh-pages
```

或在仓库根用 worktree：

```bash
git worktree add ../pages gh-pages
cp -r repo/* ../pages/          # repo/ 是 make_repo.py 的输出目录
git -C ../pages add -A && git -C ../pages commit -m "repo: 发布 v0.0.9" && git -C ../pages push
```

Pages 通常 30–60 秒内重新构建。

## 四、发布后自检

```bash
BASE=https://chenlin8023.github.io/LSTimeSeconds-iOS17

curl -s $BASE/Release   | head -10      # 200，字段齐全
curl -s $BASE/Packages  | grep -E "^(Package|Version|Filename):"

# 校验 Release 声明的 SHA256 与真实文件一致
curl -s $BASE/Packages | sha256sum
curl -s $BASE/Release  | grep -A5 SHA256

# 校验 deb 能下、哈希与 Packages 里的一致
curl -sO $BASE/debs/com.sini921.lstimeseconds_0.0.9-1_iphoneos-arm64e.deb
sha256sum com.sini921.lstimeseconds_0.0.9-1_iphoneos-arm64e.deb
```

真机上：加源 → 刷新 → 搜索插件名 → 安装 → Respring。

## 五、常见坑

| 现象 | 原因 |
|---|---|
| 加了源但商店里搜不到包 | `Release` 的 `Architectures` 没包含客户端架构；或 `Packages` 里缺 `Filename` |
| 显示"包大小/哈希不匹配" | `Release` 用了旧哈希。改完 `Packages` 必须重新跑 `make_repo.py` |
| 下载 404 | `Filename` 路径与 `debs/` 实际路径不一致（大小写敏感） |
| 所有索引 404 | Pages 分支/目录没配对，或缺少 `.nojekyll` 导致 Jekyll 过滤 |
| 索引文件被改成 CRLF 导致哈希不符 | gh-pages 分支必须加 `.gitattributes`：`* -text`、`*.deb binary` |

> 本仓库的 gh-pages 分支已经带了这个 `.gitattributes`，`Release` 里的哈希与提交字节严格一致。

## 六、可选：给源加 GPG 签名

不签名也能装（Sileo 会提示"源未签名"）。要消除提示需签名：

```bash
# 1. 生成密钥（只需一次，妥善保存私钥）
gpg --batch --gen-key <<'EOF'
%no-protection
Key-Type: RSA
Key-Length: 4096
Name-Real: Chenlin8023 Repo
Name-Email: Chenlin8023@users.noreply.github.com
Expire-Date: 0
%commit
EOF

# 2. 对 Release 做分离签名
gpg --default-key Chenlin8023 --detach-sign --armor -o repo/Release.gpg repo/Release
gpg --default-key Chenlin8023 --clearsign       -o repo/InRelease  repo/Release

# 3. 导出公钥给用户导入（或发布到 keyserver）
gpg --armor --export Chenlin8023@users.noreply.github.com > repo/public.key
```

用户导入公钥后（Sileo 内可直接从源地址导入，或 `gpg --import`），签名校验才会通过。
私钥**不要**提交进仓库；建议用 GitHub Actions Secrets 或本地签名后再推送。

## 七、为什么不用 GitHub Actions 自动发布

构建需要 macOS + Theos + clang 19 工具链（arm64e 的 chained fixups 与 `__cfstring` isa
认证都依赖这个组合），GitHub 托管的 macOS runner 上没有预装、且 clang 版本不受控，
自动构建出的二进制未必能在真机加载。当前采用"本地构建 → 手动发布"，
确保进源的每个包都是经过真机验证的那一份。
