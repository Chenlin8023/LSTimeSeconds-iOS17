# 05 · 版本策略与设置面板说明

## 一、版本策略：只发布真机验证过的构建

这个仓库只把**在 iPhone 15 Pro / iOS 17.2.1 / RootHide 上实际跑通**的版本放进越狱源。
没有实机验证的构建，即使编译全绿，也不进源。

| 版本 | 状态 | 说明 |
|---|---|---|
| `0.0.7-1` | ✅ **当前版本** | 锁屏秒数、字号缩放、上下位置调节、长按不冲突，实机验证通过 |
| `0.0.8-1` | ❌ **已撤回** | 锁屏功能正常，但**进入「设置 → LSTimeSeconds」闪退** |

## 二、0.0.8 为什么闪退

0.0.8 相对 0.0.7 只改了一处：把设置面板从"原作者预编译的 `LSTSPrefs` 二进制"换成了
本仓库源码编译的 `LSTRootListController`（`PSListController` 子类）。

- 动态库（`LSTimeSeconds.dylib`）与 `0.0.7` **完全相同**，所以锁屏秒数一切正常；
- 面板二进制通过了静态检查：`MH_DYLIB`、`NSPrincipalClass = LSTRootListController`、
  符号表有 `_OBJC_CLASS_$_LSTRootListController`、`__cfstring` isa 已补认证；
- 但真机点进设置就退出。崩溃点在 `Preferences` 进程内加载/实例化面板控制器阶段。

当时没有拿到 `Preferences` 进程的崩溃日志（`.ips`），所以没有猜测性修复。

**2026-11-02 已定位**（后来从真机抓到 `.ips`）：不是 `PSListController` 写法，
也不是 plist 路径问题。崩溃栈是
`libobjc readClass → map_images → dlopen → NSBundle principalClass → lazyLoadBundle`，
即面板二进制在加载 ObjC 元数据阶段就崩了。clang19/ld64 956 生成的 arm64e
`__DATA,__objc_data` 中，`class_t.isa` 与 `superclass` 是**无 PAC 的普通 bind/rebase**；
Xcode 产物分别是 `auth div=0x6AE1` 与 `auth div=0xB5AB`（key 2）。
`readClass` 对其做指针认证失败 → SIGBUS。完整分析与修复脚本见
[`rootless/docs/06-rootless适配.md`](../rootless/docs/06-rootless适配.md)。

## 三、现在的做法

```
vendor/LSTSPrefs.bundle/LSTSPrefs   ← 验证过的面板二进制（sha256 53205ad6…81acf）
experimental/LSTRootListController.* ← 自建控制器源码，保留但未启用
```

`build.sh` 不再编译面板，而是把 `vendor/` 里的二进制放进包里；`Makefile` 也移除了
bundle target。这样仓库构建出来的包与真机验证过的 `0.0.7-1` 一致：

- 面板二进制 sha256 与验证版**逐字节相同**；
- 面板 UI 仍是 `Root.plist` 里定义的 11 个 cell（开关 + 两个滑块 + 说明 + 注销按钮），
  由本仓库的 `layout/` 提供，中英文案也在本仓库维护。

也就是说：**只有面板的"可执行文件"是原版，UI 与文案都是本仓库自己的**。

## 四、后续要恢复自建面板的条件

1. 抓到 `Preferences` 进程的崩溃日志（`.ips`），确认崩溃栈；
2. 在真机上验证"进入设置 → 改字号 → 改位置 → 注销"全流程；
3. 验证通过后，把 `experimental/LSTRootListController.m` 移回根目录、恢复 `Makefile`
   里的 bundle target、`build.sh` 重新编译面板，再提升版本号发布。

在此之前，`experimental/` 目录仅作参考，**不要**直接启用。

## 五、装过 0.0.8 / 旧 RootHide 包怎么办

2026-11-06 起源里拆成两个 Package ID：

- RootHide：`com.sini921.lstimeseconds.roothide`（`0.0.7-1`，arm64e）
- rootless：`com.sini921.lstimeseconds`（`0.0.7-5`，arm64，`/var/jb`）

装过 0.0.8 或旧 RootHide 包（旧 ID `com.sini921.lstimeseconds`）的设备：

1. 先在 Sileo / Zebra 卸载旧包；
2. 再安装 `LSTimeSeconds (RootHide)`；
3. Respring。prefs 域仍是 `com.b4db1r3.lstsprefs`，设置可保留。

rootless 用户继续升级 `com.sini921.lstimeseconds`，不需要换包。
两个包互相 `Conflicts`，不能共存。
