# 06 · 待机显示（StandBy）与全天候显示（AOD）可行性调研

> 调研日期：2026-11-06
> 基线设备：iPhone 15 Pro / iOS 17.2.1 / RootHide（有 StandBy + AOD）；
> 　　　　　iPhone 14 Pro/Pro Max（AOD 机型）/ iOS 16.0.3 / rootless（只有 AOD，没有 StandBy）
> 基线版本：LSTimeSeconds RootHide `0.0.7-1`、rootless `0.0.7-5`
> 结论适用范围：iOS 16.0 – 17.x（不含 iOS 18 的新 StandBy 表盘改版）

> **2026-11-06 决定：暂不实施。**
> 原因：StandBy/AOD 依赖 SpringBoard 私有类与 BacklightServices，跨 iOS 17.x 小版本适配成本高；
> 一旦 hook 异常可能导致 SpringBoard 崩溃/白苹果，RootHide 环境下排查与恢复成本更高。
> 本文保留作为调研记录；现有 LSTimeSeconds 不做改动。

---

## 0. 一句话结论

| 场景 | 现状 | 可行性 | 建议 |
|---|---|---|---|
| 锁屏亮屏秒数（iOS 16/17） | 已支持 | — | 保持 |
| **StandBy 亮屏 + Digital 表盘** | 不支持 | **高** | **v1 就做这个** |
| StandBy 变暗 / 夜间红色（1Hz） | 不支持 | **低** | 不做，或只做实验分支 |
| 锁屏 AOD 暗屏（iOS 16/17） | 不支持 | **低** | 维持“暗屏暂停、亮屏恢复” |
| iOS 16 的 StandBy | 系统无此功能 | 不存在 | 只能做 AOD |

**一句话：StandBy 亮屏是唯一值得投入的窗口；一旦屏幕变暗/进入夜间模式，它和锁屏 AOD 是同一堵墙，应用层定时器绕不过去。**

另外澄清一个常见误解：StandBy 的 **Analog（模拟）表盘本来就有走动的秒针**（亮屏时）。本插件要解决的是 **Digital（数字）表盘只显示 `HH:mm`** 的问题，不是“让 StandBy 有秒针”。

### 1.2 真正相关的旧插件（都是 iOS 15/16 时代、rootless 为主）

| 插件 | 公开版本 | 支持系统 | 打包形态 | 与 StandBy/AOD 的关系 |
|---|---|---|---|---|

| **Lynx 2**（MTAC） | 2.5.4 | iOS 14 – 16.7.10 | rootful + rootless；可在 RootHide Bootstrap/Serotonin 下跑 | 只是放开系统 AOD 在低电量/专注/CarPlay 下的策略，不改刷新率 |

**关键点（也是你之前踩过的坑）：**

1. 这些插件全部是 **rootful/rootless 时代**的产物，没有一个是 **原生 roothide** 包。
2. 在 RootHide 上装它们，必须经过 RootHide 转换器或 Serotonin 注入；这正是你遇到过的“转换后不注入/无效”的同一类问题。
3. 它们 **没有解锁 BacklightServices 的 1Hz**；LastLook/Glow 是“自己实现一套常亮层”，Lynx 2 只是改系统策略。把它们当“刷新率解锁”的参考会走偏。
4. 它们都没有 StandBy 数字秒功能。

> 版本号来自公开源/商店页面，可能继续更新；真要引用，以源上当时的 control 为准。

## 2. StandBy 的内部结构（iOS 17）

### 2.1 进程与框架

StandBy 在系统内部的代号是 **Ambient**，不是 “StandBy”。它的 UI 主要由 `AmbientUI.framework` 提供，运行在 **SpringBoard 进程**里。

证据：

- `StandPad` 的 SpringBoard 模块 filter 只有 `com.apple.springboard`，并且直接 hook 运行时的 `SBAmbientPresentationController`（`isAlwaysOnPolicyActive`、`isPresented`、`_setPresented:`）。
- iOS 17 头文件里，`AmbientUI/` 下有 `AMUIAmbientViewController`、`AMUIPosterViewController`、`AMUIDateTimeViewController`、`AMUIDateTimeView`、`AMUIDateTimeDataLayerViewController`。
- SpringBoard 侧有 `AMAmbientPresentationTriggerManagerObserver`、`AMRedModeTriggerManagerObserver` 协议，以及 `SBAmbientPresentationController`（类本身在运行时存在，头文件 dump 里可能以别的文件名出现）。
- 相关的“是否进入 StandBy/是否亮着”的状态机在 `Ambient.framework`：`AMAmbientPresentationTriggerManager`（充电/磁吸/呈现状态）、`AMRedModeTriggerManager`（环境光→红色夜间模式）、`AMAmbientDefaults`（`alwaysOnEnabled`、`alwaysOnMode`、`nightModeEnabled` 等）。

### 2.2 数字时钟的刷新链路

| 类 / 方法 | 作用 | 证据文件 |
|---|---|---|
| `AMUIDateTimeViewController` | StandBy 的日期时间控制器；有 `_startUpdateTimer` / `_stopUpdateTimer` / `_updateViewWithDate:` / `_disablesUpdates` | `AmbientUI/AMUIDateTimeViewController.h` |
| `AMUIDateTimeView` | 真正显示时间的 UIView；ivar `_timeLabel`、`_dateLabel`，方法 `_updateLabels`，属性 `date`、`timeFont`、`dateFont` | `AmbientUI/AMUIDateTimeView.h` |
| `AMUIDateTimeDataLayerViewController` | 把 `AMUIDateTimeViewController` 作为数据层挂在海报上 | `AmbientUI/AMUIDateTimeDataLayerViewController.h` |
| `AMUIDefaultDateProvider` | **按分钟**驱动更新：`observeMinuteUpdatesWithHandler:`、`_minuteTimer`、`_scheduleNextMinuteTimer` | `AmbientUI/AMUIDefaultDateProvider.h` |
| `SBAmbientPresentationController` | SpringBoard 侧的 StandBy 呈现控制器；`isPresented`、`isAlwaysOnPolicyActive` | StandPad 源码（运行时 hook） |

**结论：系统数字时钟默认是“分钟级”更新，不带秒。** 这就是为什么 Digital 表盘不显示秒，也是为什么我们只要把数据源换成 1Hz 就能在亮屏 StandBy 下显示秒。

### 2.3 五种表盘不一定都走同一个 View

StandBy 表盘有 Digital / Analog / World / Solar / Float 等。`AMUIDateTimeView` 是 AmbientUI 里唯一带 `_timeLabel` 的数字时间视图，**大概率对应 Digital 表盘**；其他表盘可能由 PosterBoard/其他层渲染。

因此 v1 要明确写清楚：**只承诺 Digital 表盘**；其余表盘在真机上逐个验证，不支持的不要强行 hook。

## 3. 刷新率到底锁在哪

### 3.1 两层，不要混为一谈

```
亮屏 StandBy：
  AMUIDateTimeViewController --(我们换的 1Hz 定时器)--> _timeLabel.text
        └── SpringBoard 正常合成 --> 屏幕（可行）

变暗 / 夜间 / AOD：
  AMUIDateTimeViewController 的 timer 被停 / _disablesUpdates = YES
        └── 即使我们继续改 text
              └── BacklightServicesHost 用 Flipbook 回放已渲染帧
                    └── 应用层的新帧被丢弃 --> 屏幕不动（不可行）
```

- **第一层（应用层）**：控制器停止更新、`_disablesUpdates` 置位。这一层可以 hook。
- **第二层（显示管线）**：`BLSHAlwaysOnPresentationEngine` 的 Flipbook + 1Hz 策略。这一层才是 AOD 秒数冻结的根因。

### 3.2 相关私有 API（iOS 17.4/18.2 头文件）

| 类 / 属性 | 含义 |
|---|---|
| `BLSHAlwaysOnPresentationEngine` | AOD/StandBy 暗屏的呈现引擎；属性 `global1HzFlipbook`、`onStandby`、`alwaysFillFlipbook`、`cacheFlipbook`、`usePseudoFlipbook`；方法 `startLiveUpdates`、`startFlipbookAndEnsureCurrent`、`hostEnvironment:hostDidSet1HzFlipbook:`、`hostEnvironment:hostDidSetUnrestrictedFramerateUpdates:` |
| `BLSHFlipbookSpecification` | `framesPerSecond`、`frameCapacity`、`minimumGapDuration`、`maximumRenderInterval` 等 |
| `BLS1HzFlipbookAttribute` / `BLSGlobal1HzFlipbookAttribute` | 场景级 / 全局 1Hz Flipbook 断言；带 `checkEntitlementSourceForRequiredEntitlements:error:` 权限检查 |
| `BLSHGlobalUnrestrictedFramerateAttributeHandler` | 放开帧率限制的服务端 handler |
| `BLSHRequestLiveUpdatingAttributeHandler` | 请求“实时更新”而非 Flipbook 的 handler |
| `BLSHDisableFlipbookAttributeHandler` | 禁用 Flipbook |
| `BLSDisableAlwaysOnAttributeHandler` | 禁用 Always-On |

### 3.3 对 `docs/03` 的一处措辞修正

`docs/03` 写的是“LTPO 把刷新率锁到 1Hz，由显示驱动在硬件层面接管，App 不能改”。更准确的说法是：

- 面板本身可以跑更高刷新率；**1Hz 是 iOS 的功耗策略**，由 `BacklightServicesHost` 的 Flipbook/1Hz 机制强制执行。
- 它不是不可绕过的硬件锁；理论上可以通过 BLSH 的属性/Provider 绕过，但这些 API 有 entitlement 检查、会显著增加耗电与烧屏风险，而且随 iOS 小版本变化。
- 所以“应用层绕不过”这个结论仍然成立，但原因是**显示管线**，不是“硬件锁死”。

## 4. 可行性矩阵（按“能不能稳定发布”判断）

| 场景 | 系统是否允许实时 UI | 需要做什么 | 可行性 | 风险 |
|---|---|---|---|---|
| StandBy 亮屏 / Digital | 是（原生 Analog 秒针就在走；第三方时钟 App 也宣称 StandBy 可实时走秒） | hook AMUI 的控制器/视图，自己起 1Hz | **高** | 字体/布局；iOS 小版本类名变化 |
| StandBy 亮屏 / Analog | 系统自带秒针 | 不需要做 | — | — |
| StandBy 变暗 / 夜间 | 否（Flipbook + 1Hz） | 必须动 BLSH：关 1Hz、请求 live updating、或阻止变暗 | **低** | 耗电、烧屏、权限检查、版本脆弱 |
| 锁屏 AOD（iOS 16/17） | 否（同一套 BLSH） | 同上 + 保持锁屏时钟 timer | **低** | 同上；已有实验证明只改 timer 无效 |
| iOS 16 StandBy | 系统无此功能 | 无 | 不存在 | — |

**建议的发布边界：只发布“StandBy 亮屏 Digital 秒数”。变暗/夜间/AOD 一律不承诺，暗屏时暂停刷新。**

## 5. v1 实现方案（StandBy 亮屏 Digital 秒数）

### 5.1 包结构：独立包，不动已验证的 LSTimeSeconds

建议新包，而不是把代码塞进现有 dylib：

- 包名：`com.sini921.lstimeseconds.standby`（显示名 `LSTimeSeconds StandBy`）
- 版本：`0.1.0-1`
- 注入：`com.apple.springboard`（与现有 LSTimeSeconds 相同）
- 依赖：`mobilesubstrate`
- 与 `com.sini921.lstimeseconds` 可共存；不 Conflicts

理由：StandBy 代码一旦在 SpringBoard 里出问题，不会把已经验证过的锁屏秒数一起带进安全模式。稳定后再考虑合并。

### 5.2 Hook 点

```objc
// 只列关键点，实际实现要加 respondsToSelector / class_getInstanceVariable 兜底
%hook AMUIDateTimeViewController

- (void)viewDidLoad {
    %orig;
    [LSTStandbyDriver shared].controller = self;
}

- (void)_startUpdateTimer {
    %orig;
    // 系统开始更新（亮屏 StandBy）→ 我们也开始 1Hz
    [[LSTStandbyDriver shared] start];
}

- (void)_stopUpdateTimer {
    %orig;
    // 系统停止（变暗/离屏）→ v1 跟着停，避免做无效刷新与耗电
    [[LSTStandbyDriver shared] stop];
}

- (void)_updateViewWithDate:(NSDate *)date {
    %orig;
    // 系统按分钟刷新后，立刻把秒补回去，防止被覆盖
    [[LSTStandbyDriver shared] applySecondsToCurrentView];
}

%end

%hook AMUIDateTimeView

- (void)_updateLabels {
    %orig;
    [[LSTStandbyDriver shared] applySecondsToView:self];
}

%end
```

### 5.3 定时器

- 用 `NSTimer timerWithTimeInterval:target:selector:userInfo:repeats:`（target/selector），**不要用 ARC 持有的全局 block 字面量**。`0.0.7-3` 的安全模式就是全局 block 的 isa 没有 PAC，`objc_retain` 时 SIGBUS。
- 1Hz，主 RunLoop `NSRunLoopCommonModes`，首次 fire 对齐到下一个整秒 +10ms（沿用 `0.0.7-5` 的做法）。
- 启动/停止条件：
  - `controller.view.window != nil`；
  - 系统 `_startUpdateTimer` 被调用（说明当前是亮屏 StandBy）；
  - 若 `_disablesUpdates == YES`，暂停（需要真机确认它是否在变暗时置位；若不置位，用 BLS 背光状态兜底）。
- 离开 StandBy / 锁屏 / 熄屏时停表；回来时由 `_startUpdateTimer`/`viewWillAppear` 重新拉起。

### 5.4 文本与格式

```objc
NSString *fmt = [NSDateFormatter dateFormatFromTemplate:@"jms"
                                                 options:0
                                                  locale:[NSLocale currentLocale]];
// 12h → "h:mm:ss a"；24h → "HH:mm:ss"
// 若 fmt 已包含 's'，不要重复追加
```

- 先让系统 `_updateLabels` 跑完（日期、字体、布局都按系统来），再覆盖 `_timeLabel.text`。
- 日期标签不动。
- 如果系统格式带 AM/PM，秒要插在 AM/PM 前面（`dateFormatFromTemplate` 已经处理好顺序）。

### 5.5 布局：三种可选，v1 选第一种

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 整体缩小** | 按 `sizeWithAttributes:` 实测 `HH:mm:ss` 宽度，按可用宽度等比缩小 `timeFont` | 实现简单、视觉统一 | 数字会明显变小 |
| B. 小号秒 | 保留 `HH:mm` 原字号，在右侧加一个小号 `:ss` | 好看、主时间不缩小 | 需要额外 label/约束，代码多 |
| C. 秒单独一行 | 在日期下方加一行小号秒 | 最不干扰 | 偏离“时钟显示秒”的直觉 |

v1 用 A：

1. 第一次拿到 `AMUIDateTimeView` 时，把 `timeFont.pointSize` 缓存为“原始基准”（associated object），之后永远从基准算，避免每秒震荡（LSTimeSeconds 的老坑）。
2. 计算可用宽度：`view.bounds.width - 左右安全边距`（真机测，Digital 表盘可能占满屏宽）。
3. `scale = min(1.0, available / measuredWidth)`；`font = [baseFont fontWithSize:baseSize * scale]`。
4. 设置 `_timeLabel.font`、`_timeLabel.adjustsFontSizeToFitWidth = YES`、`minimumScaleFactor = 0.5`、`numberOfLines = 1`。
5. 只在 `scale` 与当前值差 >0.5pt 时改字体，防抖。
6. 若系统在 `updateConstraints` / `layoutSubviews` 里把字体重置，一并 hook 后重新应用；不要每秒 `setNeedsLayout` 造成布局抖动。

### 5.6 设置项

v1 不新建设置面板（现有 `vendor/LSTSPrefs.bundle` 是编译好的二进制，只有 `Info.plist`，没有可编辑的 `Root.plist`；加开关必须重编面板，风险大）。

- 读现有 `com.b4db1r3.lstsprefs` 的 `isEnable` 作为总开关；
- 新增键 `standbySeconds`，缺省 `YES`；高级用户可用 `defaults write` 关闭；
- 以后要 UI，再单独做一个面板，不要动已验证的 vendor 面板。

### 5.7 失败兜底

- 所有类/方法用 `NSClassFromString` + `respondsToSelector` 判断；类不存在就什么都不做。
- hook 里不要抛异常；所有 KVC/ivar 读取包 `@try`。
- 日志沿用 `/var/mobile/Library/LSTimeSeconds.log`，加 `[StandBy]` 前缀，256KB 轮转。
- dylib 里如果有 ObjC 类（driver），arm64e 的 `__objc_data` 也要做 PAC 补丁；复用 `tools/patch_arm64e.py`，不要只补 `__cfstring`。

## 6. 如果一定要做“变暗/夜间秒数”（不推荐发布）

这是一条独立的 R&D 线，不要混进 v1。可验证的假设按顺序：

1. **确认停更信号**：在 `AMUIDateTimeViewController` 上打印 `_disablesUpdates`、`view.window`、`_dateTimeView._timeLabel.text`，确认变暗时到底是 timer 停了、还是 text 改了但没上屏。
2. **只改应用层**：hook `_disablesUpdates` 为 NO、保持 1Hz timer，观察变暗时是否仍然冻结。预计冻结（与现有 AOD 实验一致）。
3. **动 BLSH**：在 SpringBoard 的 scene/environment 上尝试
   - `BLSHGlobal1HzFlipbookProvider.global1HzFlipbook = NO`；
   - 或添加 `BLSGlobal1HzFlipbookAttribute` / `BLSDisableFlipbookAttribute` 的反向断言；
   - 或让 StandBy 场景请求 `BLSHRequestLiveUpdatingAttribute` / `BLSHGlobalUnrestrictedFramerate`。
   这些属性有 entitlement 检查，需要同时 hook `checkEntitlementSourceForRequiredEntitlements:error:`。
4. **阻止变暗**：hook `SBAmbientPresentationController.isAlwaysOnPolicyActive` 返回 YES（StandPad 用过这招），或改 `AMAmbientDefaults.alwaysOnMode`。这只能让 StandBy 保持“策略激活”，不等于绕过 1Hz；而且会让屏幕整夜亮着。
5. **验收**：30 分钟耗电、机身温度、烧屏风险评估、iOS 17.0/17.1/17.2 三版回归。

预期结果：能做出 demo，但不适合作为稳定功能发布；耗电和烧屏是真实代价，且 iOS 小版本随时可能改类名/属性。

**更省事的替代方案**：设置 → 待机显示 → 显示屏 → “永不”，让系统保持 StandBy；代价是强制红色夜间模式、耗电和烧屏。这不是插件能“优化”掉的，是 Apple 的产品取舍。

## 7. 打包与版本：rootless 还是 roothide

### 7.1 当前稳定版是什么

| 形态 | 版本 | 架构 | 安装前缀 | 链接 | 验证设备 |
|---|---|---|---|---|---|
| **RootHide（原生 roothide）** | `0.0.7-1` | `iphoneos-arm64e` | 无（根目录） | `libsubstrate_roothide.tbd` → `@loader_path/.jbroot/usr/lib/libsubstrate.dylib` | iPhone 15 Pro / 17.2.1 |
| **rootless** | `0.0.7-5` | `iphoneos-arm64` | `/var/jb` | `-lsubstrate` + rpath `/var/jb/Library/Frameworks`、`/var/jb/usr/lib` | iOS 16 AOD 机型 / 16.0.3 |

两版同 Package 名、不同 Architecture，源站按架构分发；**不能混装，也不能用转换器把 rootless 转成 roothide**。

### 7.2 新插件以哪条线为基准

- **StandBy 只在 iOS 17 有**，而你的 17.2.1 设备是 RootHide → **以 roothide `0.0.7-1` 的构建形态为基准**（`THEOS_PACKAGE_INSTALL_PREFIX=` 空、`libsubstrate_roothide`、arm64e、`iphoneos-arm64e`）。
- 但代码逻辑建议用 **rootless `0.0.7-5` 的最新改进**：日志轮转、首次 fire 对齐整秒、不靠 `g_isScreenOff` 布尔值停表。`0.0.7-1` 的旧停表逻辑（熄屏就 `stopTimer`）在 iOS 16 上已被证明会冻结，不建议照抄。
- **iOS 16 的 AOD 秒数**（如果以后要做）才用 rootless 线；StandBy 功能在 iOS 16 上不存在，不需要 rootless 版。
- 如果一定要同时发布两种形态：同一份源码，两个 Makefile/构建脚本，产出两个 deb；**不要**做一个包再转换。

### 7.3 为什么不能参考旧 AOD 插件的版本

- LastLook / Glow / Lynx 2 / Photon 都是 **rootful/rootless** 包，没有原生 roothide。
- 在 RootHide 上使用它们要走转换器/Serotonin；你之前遇到的“转换后不注入/无效”就是这一类。
- 它们的 AOD 实现是自建常亮层（LastLook/Glow）或系统策略开关（Lynx 2），**不是** BLSH 1Hz 解锁；没有可复用的 roothide 构建基线。
- 所以：**只参考它们的思路，不参考它们的包格式，更不要把它们的 deb 当依赖。**

## 8. 真机验证清单

### 8.1 先做运行时探针（不改功能）

在 SpringBoard 注入一个只打印的 dylib，确认：

- `dlopen("/System/Library/PrivateFrameworks/AmbientUI.framework/AmbientUI", RTLD_NOW)` 成功；
- `NSClassFromString(@"AMUIDateTimeViewController")`、`AMUIDateTimeView`、`AMUIDateTimeDataLayerViewController` 存在；
- `AMUIDateTimeViewController` 的 ivar：`_disablesUpdates`、`_dateProviderToken`、`_dateTimeView`；
- `AMUIDateTimeView` 的 ivar：`_timeLabel`、`_dateLabel`；
- 进入 StandBy 亮屏后，打印 `_timeLabel.text`、`view.window`、`_disablesUpdates`；
- 手动变暗/夜间后，再打印一次，确认是 timer 停、还是 text 不改、还是改了不上屏。

### 8.2 功能回归

- Digital 表盘：`HH:mm:ss` 每秒递增；12/24 小时制正确；AM/PM 位置正确。
- 字体：不超出屏幕；不抖动；离开再进入不叠加缩放。
- 日期：不被改坏；长按编辑 StandBy 表盘不冲突。
- 离开 StandBy（抬起/解锁/停止充电）→ timer 停；回来 → 恢复。
- 变暗/夜间 → 秒停（v1 预期行为），屏幕不冻结、不发热。
- 锁屏亮屏 → 现有 LSTimeSeconds 不受影响；锁屏海报编辑不冲突。
- 连续 30 分钟：耗电、温度、无 SpringBoard 崩溃/安全模式。
- iOS 17.0 / 17.1 / 17.2.1 各跑一次（类名/行为可能不同）。

### 8.3 失败判据

出现以下任一情况，v1 不发布：

- StandBy 亮屏下秒数不走，或走了但被系统每分钟覆盖；
- 字体/布局导致时钟被裁切；
- 离开 StandBy 后 timer 不停，耗电明显；
- SpringBoard 崩溃或安全模式；
- 影响锁屏秒数/海报编辑。

## 10. 最终建议

1. **做 v1：StandBy 亮屏 + Digital 表盘 + 秒数**，独立包，roothide arm64e，基于 `0.0.7-1` 的构建形态 + `0.0.7-5` 的定时器逻辑。
2. **不做** StandBy 变暗/夜间秒数，也**不做**锁屏 AOD 秒数；这两个是同一堵 BLSH 墙，投入产出比很低。
3. **不要**参考 StandByPlus / AODClock / StandByEnhancer（不是越狱插件或查无此物）；LastLook/Glow/Lynx 2 只参考思路，不参考包格式。
4. **不要**做 rootless↔roothide 转换；同一份源码两条构建线，各自出包。
5. 先跑 8.1 的运行时探针，确认 `AMUIDateTimeViewController` 在你的 17.2.1 上确实存在、且 Digital 表盘走它，再动手写功能。
